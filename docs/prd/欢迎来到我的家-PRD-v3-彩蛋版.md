# 《欢迎来到我的家》· PRD v3（彩蛋版）

> 版本：v3.0 · 2026-11-07 · 状态：待评审 · **取代 PRD v2（二维码版）**
> 变更来源：用户对本轮产品评估的四条拍板（见 0.1）
> 承继范围：v2 的全部工程结论继续有效 —— 纯 HTTP 局域网、二维码深链、游戏页零摄像头、前端 100% 渲染、固定内网 IP、服务端判题。**v3 只改玩法层，不改技术底座。**

## 0. 本轮决策与变更

### 0.1 四条拍板及落地方式

| # | 用户决策 | v3 落地 |
|---|---|---|
| 1 | 「第一点还不错，而且扫出来应该有一个彩蛋特效」 | 采纳「答题从门票改为彩蛋」，并**新增 E1 发现彩蛋特效**：扫码瞬间即爆开视觉特效 + 人偶揭晓，零门槛、不依赖答题。见第 8 章 |
| 2 | 「第二点不要限制，题目是主人设置的，难不难由主人决定」 | **撤回 v2→v3 评估里「题目改成观察/空间线索」的建议**。题目类型、内容、难度、提示、尝试次数全部由主人自由配置；系统不引导、不校验、不限制题型。**只在机制层兜底：答错不影响主流程**（限制的是后果，不是难度）。链式线索降为可选字段。见 7.4 |
| 3 | 「终局可以主人来定」 | 终局不写死任何形式：触发条件、标题文案、图片、合体模型、实体奖励兑换语全部主人自定义。见第 9 章 |
| 4 | 「可以作为关卡设计的一部分，主人可以设置多种不同类型的关卡，单人或者多人，优先保证单人场景能够实现」 | 新增**关卡系统**（房间级 `game_mode` × 卡片级 `level_type`），主人逐卡配置类型。**MVP P0 只实现单人可独立通关的类型**，多人类型仅预留枚举与数据结构，P2 实现。见第 7 章 |

### 0.2 v2 → v3 变更对照

| 项 | v2 | **v3** |
|---|---|---|
| 内核 | 你得懂我，才见得到 TA | **找到你就见到 TA，懂 TA 才听见 TA 的故事** |
| 答题作用 | 门票：答对才解锁人偶 | **彩蛋题：解锁第二层内容，不解锁人偶** |
| 扫码瞬间 | 灰剪影 + 题目 | **E1 发现彩蛋特效 → 剪影溶解 → 3D 人偶 → 收入收藏册** |
| 揭晓特效 | 仅答对后 1 段（1.5–2.5s） | **两段独立演出**：E1 发现（扫码即得）、E2 秘密（答对才有） |
| 答错后果 | 次数 -1、冷却 10s、错 3 次退回 locked | **无惩罚、无冷却、不锁定、可跳过、随时可再挑战** |
| 题目 | 主人设单选/简答 | **完全不变，主人自由**（仅新增可选 `next_clue`） |
| 关卡 | 无概念，所有卡同一玩法 | **新增关卡系统**，主人逐卡选类型；单人为先 |
| 终局 | 无 | **新增**，主人自定义条件与内容 |
| 收藏册 | 已解锁人偶 | 已解锁人偶 + **彩蛋 0/1 角标** + 终局页入口 |
| 模型保护 | 判题通过才签发主模型 URL | **两级 ticket**：扫码签 base ticket（主模型），判题通过签 secret ticket（E2 资产） |
| 排期 | 5–7 天 | **5–8 天**（多出 E1 特效与关卡配置，砍刀线兜底） |

### 0.3 一条必须说清的连锁后果：模型保护机制迁移

v2 里「答对才签发模型 URL」是为了防 F12 跳关。v3 人偶改成扫码即得，**主模型不再需要判题保护**，但也不能让没扫到卡的人猜 URL 直接下载。因此签名机制不删除，而是**迁移 + 分级**：

- `base` ticket：服务端校验 token 合法 → 扫码时随题目响应一起签发，用于拉取主 GLB / 基础谜底。
- `secret` ticket：仅 `POST /api/play/answer` 判定通过后签发，用于拉取 E2 的隐藏故事、第二形态 GLB、悄悄话。
- 答案加盐哈希、服务端判题、限流**全部保留**（现在保护的是彩蛋，不是人偶）。

> 若不迁这一层，文档会出现「扫码就给模型」与「未解锁请求 403」自相矛盾。纯静态版（附录 A）因此仍不推荐。

## 1. 产品概述

### 1.1 定位

在家里跑起来的**二维码寻宝 + 双层彩蛋 + 3D 收藏**游戏。主人把照片生成的 3D 人偶做成实体卡藏在家中，逐卡配置关卡类型与题目；客人连 WiFi 打开游戏页，找到卡、扫码，**立刻拆开一个彩蛋**见到人偶；有余力再挑战主人留的题，答对拆开第二层秘密。

### 1.2 内核（v3 改写）

> **找到你就见到 TA，懂 TA 才听见 TA 的故事。**

v2 的「你得懂我，才见得到 TA」对老友成立，对小朋友和普通客人是把人挡在门外。v3 把「见到」变成无条件的欢迎，把「懂我」变成可选的加分——内核不变，门槛后移。**「欢迎来到我的家」与机制不再打架。**

### 1.3 双层彩蛋模型（v3 核心）

| 层 | 触发 | 内容 | 门槛 | 保护 |
|---|---|---|---|---|
| **E1 发现彩蛋** | 扫到卡 / 输短码 | 全屏特效 + 3D 人偶 + 名字 + 基础故事 + 收入收藏册 | **零门槛，人人必得** | base ticket |
| **E2 秘密彩蛋** | 答对该卡题目 | 隐藏故事 / 第二形态 / 主人悄悄话 / 星标 / 专属特效 | 主人可设为「不启用」 | secret ticket |

**铁律：E1 永远先给、必给、不可被答题失败阻塞。** 任何网络抖动、判题故障、答错、跳过，都不影响客人拿到人偶。

### 1.4 三个魔法时刻（v3 更新）

| 时刻 | 画面 |
|---|---|
| M1 照片长成人偶 | 布置期：上传照片 → 风格化 → Lux3D 图生 3D → 3D 小人出现在预览里 |
| M2 拆开彩蛋 | 客人翻到书架第二层的卡 → 扫码 → **星光/纸屑自卡面爆开、屏闪轻震、剪影翻牌溶解** → 3D 人偶浮起旋转（E1） |
| M3 听见秘密 | 客人点了「再听听 TA 的故事」→ 答对主人留的题 → **金色光边向内收拢、隐藏故事逐行浮现、悄悄话气泡** → 收藏册落下一颗星（E2） |

### 1.5 成功标准

| 指标 | 目标 |
|---|---|
| 连 WiFi → 看见第一次彩蛋特效 | ≤ 30 秒，无需安装 / 登录 / 授权摄像头 |
| **零卡关** | 100% 试玩客人**不看答案、不答题**也能见到至少 1 个人偶并收入收藏册 |
| E1 闭环完整率 | ≥ 95%（扫码 → 特效 → 人偶 → 收藏） |
| 彩蛋题参与率 | ≥ 50%（观察值，不作为准入指标） |
| 设备覆盖 | iOS Safari / Android Chrome / 桌面浏览器均可完整通关 |
| 首屏 / E1 特效起播 / 主模型出现 | < 2s / < 300ms / < 3s |
| 并发 | ≥ 8 台设备，进度不串号 |
| 网络 | 游戏期可完全断外网，仅靠局域网 |

### 1.6 非目标（v3 更新）

AR / WebXR / 摄像头识别、原生 App、账号体系、云托管、无标记空间锚点、实时 PVP、贴纸电商。
**新增非目标**：不限定题目类型与难度、不替主人生成题目、不在 MVP 实现多人关卡、不内置固定终局剧本。

## 4. 系统架构

```
[ 主人家一台电脑 / NAS · 固定内网 IP，例如 192.168.1.50 ]
  ┌──────────────────────────────────────────────┐
  │ 单进程服务 :8080（纯 HTTP，无需 TLS）          │
  │  ├─ 静态：主人端 / 客人端 H5 / GLB / 剪影 PNG │
  │  ├─ API：房间、关卡配置、扫码、判题、进度、终局│
  │  ├─ SQLite：./data/home.db                    │
  │  └─ 资产：./data/photos / models / cards.pdf  │
  └──────────────────────────────────────────────┘
        ▲ http://192.168.1.50:8080/           ← 欢迎码
        ▲ http://192.168.1.50:8080/d/<token>  ← 每张实体卡的二维码
        │
  [ 客人手机 ] 系统相机 / 微信扫一扫 →「在浏览器中打开」→ 系统浏览器
        └─ 全程无 getUserMedia、无 WebXR、无摄像头画面
```

### 4.1 渲染边界（不变）

- **渲染 100% 在前端**：Three.js / `<model-viewer>` 画 E1/E2 特效、3D 人偶、展柜；Canvas 2D 画粒子；WebAudio 合成音效。服务端不生成任何画面、不接收任何图像、不引第三方 CDN。
- **服务端四件事**：静态托管、token 校验、**E2 判题**、进度/关卡/终局数据存储。
- GLB 是主人本机静态文件，前端按需拉取，不是服务端渲染。

### 4.2 扫码链路时序（v3 核心）

```
客人连 WiFi → 扫欢迎码 → 首页填昵称（guest_id / room_code 存 localStorage）
  → 在家里找到实体卡 → 系统相机 / 微信扫一扫
  → 浏览器打开 http://192.168.1.50:8080/d/<token>?r=<room_code>
  → 服务端校验 token + 房间 live
  → 返回 { 题目(可选), 基础谜底, base_ticket, level_type, E1 特效配置 }
  → 【E1】立刻起播发现彩蛋特效 → 剪影溶解 → 3D 人偶 → 收入收藏册（不可被阻塞）
  → 若该卡 level_type 含彩蛋题：页面出现「再听听 TA 的故事」入口
       ├─ 客人不点 / 点了跳过：保持已收藏，随时可回来
       ├─ 答错：温和反馈 + 可选提示，无冷却、无扣次、不锁定
       └─ 答对：服务端签发 secret_ticket → 【E2】秘密彩蛋演出 → 收藏册加星
  → 检查终局条件 → 达成则弹出主人配置的终局页
  → 继续找下一张 / 扫码跳回自动恢复会话
```

**关键设计**：扫码会离开或重开页面，所以 `guest_id`、`nickname`、`room_code` 必须存 localStorage；页面不做「必须停留在首页」的假设。

### 4.3 网络与 IP 稳定性（沿用 v2，不变）

| 约束 | 处理 |
|---|---|
| 卡片是长期物料，二维码写死 IP | 布置第一步：路由器绑定 DHCP 静态租约或手动固定 IP，端口固定 8080 |
| IP 变了 | 导卡时自动写入当前 LAN IP 并提示重印；已印卡用短码兜底（与 IP 无关） |
| WiFi 无外网导致手机切蜂窝 | 首页自检提示「关闭移动数据 / 确认连的是主人家 WiFi」 |
| 路由器 AP / 访客隔离 | 主人自检页显示 LAN IP + 客人连通测试按钮 |
| 微信内置浏览器可能拦私有 IP | 引导「在浏览器中打开」；首页固定提示用 Safari / Chrome；需真机实测 |
| mDNS `welcome.local` | 仅备选，不写进二维码 |

### 4.4 判题与资产保护的新分工

| 资产 | 何时可拉 | 凭证 |
|---|---|---|
| 主 GLB、基础故事、原图 | **扫码后立刻** | 服务端校验 token 后签发的 `base_ticket`（60s） |
| E2 隐藏故事、第二形态 GLB、悄悄话 | **仅判题通过后** | `secret_ticket`（60s） |
| 答案哈希、同义词表、他人进度、`hide_hint` | 永不下发 | — |

## 5. 二维码与实体卡规格

### 5.1 URL 格式（不变）

```
http://192.168.1.50:8080/d/<token>?r=<room_code>
```

`token` 为 10 位 base62 随机串（不用自增 ID，防枚举），`r` 为房间码；服务端校验房间处于 `live`。

### 5.2 卡片印刷规范（文案微调）

| 项 | 规格 |
|---|---|
| 载体 | 300g 卡纸 / 哑光贴纸 / 亚克力立牌，可做成可带走的周边 |
| 主视觉 | 人偶黑色剪影插画，不透露五官与颜色 |
| 二维码 | ≥ 3cm × 3cm，纠错等级 H，哑光、避免覆膜反光 |
| 短码 | 6 位大写字母数字，印在二维码下方 |
| 文案 | 一句主人写的藏匿线索 + **「扫我，拆开一个彩蛋」**（v2 为「扫我，回答一个问题」） |
| 藏法 | 书架、相框背面、抽屉、书页内、植物后；稀有卡藏更深处 |
| 备用 | 每张卡可生成备用二维码（不同 token 指向同一人偶） |

## 6. 核心流程

### 6.1 主人（布置期，15–25 分钟 / 6 个人偶）

```
固定内网 IP → 创建房间 → 上传照片 → [风格化 → Lux3D 图生 3D → GLB → Blender 清理/导出剪影]
→ 写名字与基础谜底 → 【设计关卡】逐卡选 level_type、按自己意愿出题、选 E1 特效主题、填 E2 彩蛋内容
→ 【配置终局】选触发条件、写文案/传图/填实体奖励兑换语
→ 系统生成 token / 短码 / 二维码 → 一键导出卡片 PDF → 打印并藏好 → 贴门口欢迎码 → 开局 → 看板
```

> 主人可以在同一个房间里混用不同关卡类型：有的卡只有彩蛋、有的卡带题、有的卡带线索接下一张。**这是「多种不同类型的关卡」的落点。**

### 6.2 客人（单人主线，P0 必须完整可通）

```
连 WiFi → 扫欢迎码 → 首页（填昵称、看规则、看到「共 6 位在等你」）
→ 找卡 → 扫码 / 输短码
→ 【E1】彩蛋特效爆开 → 见到 3D 人偶 → 已收入收藏册（到此已算通关一张）
→ 可选：「再听听 TA 的故事」→ 答题
     ├─ 答错：温柔反馈，可再看提示，可无限重试，可跳过
     └─ 答对：【E2】秘密彩蛋 → 收藏册加星
→ 继续找下一张 → 条件达成 → 主人配置的终局页 → 结算分享卡
```

### 6.3 主人看板（进行中）

在线客人、每人「已发现 / 已收藏 / 彩蛋挑战 / 彩蛋解锁 / 终局是否达成」、哪张卡被找最久、哪道题错得最多。主人可口头给提示，这是现场社交的核心。

## 7. 关卡系统（v3 新增）

### 7.1 两层结构

- **房间级 `game_mode`**：整局怎么组织。
- **卡片级 `level_type`**：每张卡是什么玩法。主人逐卡配置，房间可给默认值，单卡可覆盖。

### 7.2 类型枚举与范围（**单人优先**）

| 层 | 类型 | 说明 | 优先级 |
|---|---|---|---|
| `game_mode` | `solo` | 每位客人独立找卡、独立收藏、独立看终局 | **P0（MVP 唯一实现）** |
| `game_mode` | `race` | 多人竞速，看板显示谁先集齐 | P2 |
| `game_mode` | `coop` | 每人拿不同颜色卡，需合力拼齐才开终局 | P2 |
| `level_type` | `discovery` | 纯发现：只有 E1，无题 | **P0** |
| `level_type` | `bonus_quiz` | 发现 + 主人自设彩蛋题 → E2（**默认类型**） | **P0** |
| `level_type` | `clue_chain` | 主人可选填 `next_clue`，指向下一张卡；**不填则等同 discovery** | P1 |
| `level_type` | `duo_scan` | 需两名客人各扫一次才开 E2 | P2 |
| `level_type` | `timed` | 限时挑战，主人自定秒数 | P2 |

> 枚举是给主人用的配置项，不是必须全做。**数据结构一次预留到位，实现按优先级推进**，避免 v4 改表。

### 7.3 单人场景优先原则（硬约束）

1. **P0 验收以「一位客人、一台手机、无其他在线者」为准**：所有 P0 关卡类型必须能在这条件下从第一张卡走到终局。
2. 多人类型（`race` / `coop` / `duo_scan`）在 P0 阶段**不出现在主人可选列表里**，只在数据模型与 API 中预留；界面显示「即将上线」而非可点击选项，避免主人配了却跑不起来。
3. 终局触发条件不得依赖「其他客人已完成」，除非 `game_mode` 明确为多人模式。
4. 多人模式实现时，不得破坏单人路径：同一房间 `solo` 仍须完整可通。

### 7.4 主人自由出题原则（对第 2 条拍板的边界）

> **系统限制的是「答错的后果」，不是「题目的难度」。**

- 题目内容、题型（单选 2–4 项 / 简答 / 主人自定）、难度、是否给提示、提示内容、尝试次数上限、是否启用该题 —— **全部由主人决定**，系统不引导、不校验、不评分、不推荐改写。
- 主人可以把题出得极难、极私密、无厘头，甚至不给提示；这是产品要保留的「主人味道」。
- 机制层唯一硬约束：**无论题多难、错多少次，E1 已给的人偶和收藏不会被收回，也不会阻塞终局判定中的「已发现」计数**。答错只影响 E2，且主人设置的 `max_attempts` 耗尽后仍允许「跳过 / 稍后再试」，不做全局锁定。
- 上一轮评估里建议的「题目改成观察题 / 空间线索 / 链式」**不采纳为规则**，仅作为 `clue_chain` 类型的**可选**能力存在（主人想用才填 `next_clue`）。

### 7.5 主人端关卡配置界面要素

| 组 | 字段 |
|---|---|
| 基础 | 关卡类型、是否启用彩蛋题 |
| 题目 | 题干、选项 / 简答、正确答案、提示、**尝试次数上限（可填 0 表示不限）**、答错文案 |
| E1 | 特效主题（星光 / 纸屑 / 泡泡 / 火花）、是否播放音效、基础谜底故事 |
| E2 | 是否启用、隐藏故事、第二形态 GLB（可选）、悄悄话、专属特效、收藏册星标 |
| 线索 | `next_clue`（可选）、卡面藏匿线索、藏匿位置备注（仅主人可见） |
| 预览 | 主人可完整走一遍「扫码 → E1 → 答题 → E2」，不产生客人进度 |

## 8. 彩蛋特效规格（v3 新增，第 1 条拍板重点）

### 8.1 E1 发现彩蛋（扫码即爆，必现）

| 时间 | 画面 / 反馈 |
|---|---|
| 0–0.3s | 页面中央卡片「翻牌」展开 + 一道白光扫过，轻震 1 次 |
| 0.3–1.0s | 粒子自卡面向外爆散（星光 / 纸屑 / 泡泡 / 火花，主人可选），WebAudio 合成上行三音 |
| 1.0–2.0s | 灰剪影自下而上溶解 → **3D 人偶浮起、缓慢自转**（纯 WebGL） |
| 2.0–2.6s | 名字 + 一句话淡入 → 底部「已收入收藏册」 |
| 2.6s 后 | 停驻在人偶视图，提供**「再放一次」**按钮；页面底部出现「再听听 TA 的故事」（若该卡有题） |

**设计意图**：把「找到」这件事立刻兑现成一个拆礼物的瞬间，不让客人先掏手机跳浏览器、再被考一道题才拿到回报。E1 的语言是**向外爆开**，E2 是**向内收拢**，两者视觉上必须一眼可分。

### 8.2 E2 秘密彩蛋（答对才有）

1. 答对反馈（对勾 + 轻音效），画面四周金色光边向内收拢。
2. 可选：人偶切换第二形态 GLB / 加一层描边。
3. 隐藏故事逐行浮现 → 主人悄悄话气泡。
4. 收藏册该人偶落下一颗星，角标从「彩蛋 0/1」变「1/1」。
5. 总时长 1.5–2.5s，同样可重播。

### 8.3 实现与资源约束

- Canvas 2D 粒子层 + CSS transform + Three.js 模型，**不引第三方动效库 / CDN**；音效用 WebAudio 现场合成，不加载音频文件。
- 粒子数按设备分档：高 120 / 中 60 / 低 24；低档只保留翻牌 + 淡入。
- 主题色、粒子形状、音效开关由主人在关卡里配置，配置随 `level` 数据下发。
- **「再放一次」是 P0**：小朋友会反复点，这是彩蛋玩法的主要复玩点。

### 8.4 无障碍与降级

- `prefers-reduced-motion: reduce` → 直接跳到静帧人偶，不播粒子。
- 首帧 > 300ms 未起播 / WebGL 初始化失败 / 低电量低性能 → 自动降级为 CSS 翻牌 + 淡入，**E1 内容照给，绝不白屏**。
- 特效播放期间不阻塞交互，可随时点击跳过。

## 9. 终局（v3 新增，第 3 条拍板）

### 9.1 原则

**终局内容 100% 由主人定义**，系统只提供容器与触发判定，不内置固定剧本、不替主人写文案。

### 9.2 触发条件（主人任选其一）

| 条件 | 含义 |
|---|---|
| `all_collected` | 发现全部人偶（**默认，最友好，不含彩蛋题**） |
| `count_gte: N` | 发现满 N 个即可 |
| `all_eggs` | 发现全部 + 解锁全部 E2（主人想做硬核局时选） |
| `manual` | 主人在看板手动开启（适合生日会统一揭晓） |

> 单人模式下条件不得依赖他人进度。若主人选了 `all_eggs`，首页应提示「这一局要答完题才能看到结局」，把难度选择显式告知客人。

### 9.3 主人可填内容

标题、正文（多行）、图片 / 全家福、可选合体 3D 模型、结语音效、**实体奖励兑换语**（例：「拿着这一页去找主人，换一张贴纸」）、分享卡文案。全部可选，至少填一项即可开局。

### 9.4 呈现

条件达成 → 全屏终局页（可配置是否复用 E1 特效主题）→ 收藏册永久入口可回看 → 结算分享卡。主人端提供「预览终局」，不产生客人进度。

## 13. 状态机（v3 重写）

**房间**：`draft → live → paused → live / ended`。

**客人进度（每 guest × doll）**：

```
locked ──扫到 token / 输短码──> discovered（E1 演出）
   discovered ──演出结束 / 跳过──> collected（幂等，终态之一，不可回滚）
   collected ──该卡启用彩蛋题且客人点入口──> egg_answering
   egg_answering ──答错──> egg_answering（无冷却、不锁定；按主人配置给提示/答错文案）
   egg_answering ──跳过 / 离开──> collected（随时可再进入 egg_answering）
   egg_answering ──答对──> egg_unlocked（E2 演出）──> collected + 星标
```

**终局（房间 × 客人）**：`pending → reached`，由 `finale.trigger` 判定；`reached` 后收藏册永久可回看。

> 不变规则：同一张卡可被多位客人分别扫码、分别发现、各自挑战彩蛋、各自收藏。
> **v2 的「错 3 次退回 locked + 冷却 10s」整体删除。**

## 14. 交互与视觉规格

### 14.1 剪影

卡面黑色剪影插画；页面解锁前灰剪影占位，带 1–2% 呼吸缩放，角标「还没见到 · 1/6」。不泄露五官、颜色、服饰纹理。

### 14.2 E1 与 E2 演出

见第 8 章。两段演出**视觉方向相反**（向外爆 / 向内收），音色也不同，避免小朋友以为是同一个动画重播。

### 14.3 3D 展柜

收藏册里每个人偶一张卡；点开全屏 3D 视图可旋转/缩放，背景纯色或柔和渐变，不用摄像头。未发现的位置显示灰剪影。模型按需加载，未发现不请求 GLB。

### 14.4 文案与音效

语气温柔私密；答错用**主人配置的 `wrong_text`**（默认「还差一点点」「再想想那天……」）；答对「原来你记得。」音效：E1 上行三音、E2 柔和收拢音、收册翻页音。不做循环 BGM。

### 14.5 首页固定提示

> 「请连接主人家 WiFi，并用 Safari / Chrome 打开本页；微信内可能无法正常访问。」

## 16. 异常与边界态

| 场景 | 期望表现 |
|---|---|
| 没连主人家 WiFi / 手机切蜂窝 | 首页提示确认 WiFi、暂时关闭移动数据 |
| 路由器 AP / 访客隔离 | 主人自检页报警；客人看到连通失败说明 |
| 用微信扫一扫打开 | 引导「在浏览器中打开」；能加载则正常玩 |
| 二维码磨损 / 反光 | 输 6 位短码；主人可生成备用 token 重印 |
| 主人电脑 IP 变了 | 已印二维码失效 → 短码仍可用；提示重新导出 PDF |
| 改 URL 猜别的 token | 不可枚举 + 服务端校验 → 「这张卡不属于本局」 |
| 扫码后跳新标签 / 离开首页 | localStorage 恢复会话，收藏册不丢 |
| ★ 判题接口超时 / 服务异常 | **E1 与收藏照常完成**，页面提示「故事稍后再来」，不白屏、不回滚 |
| ★ 彩蛋题答错 / 次数用尽 / 跳过 | 显示主人配置的答错文案与可选提示；不冷却、不锁定、随时可再挑战 |
| ★ 主人把题出得无人能答 | 不影响 E1、不影响 `all_collected` 终局；主人可改选 `all_eggs` 显式提高难度 |
| ★ 主人未启用某卡的彩蛋题 | 该卡只有 E1，页面不出现答题入口，收藏册不显示星位 |
| ★ 主人配置了 P2 多人关卡类型 | P0 界面不可选；若配置 JSON 里出现，服务端按 `discovery` 降级处理，保证单人可通 |
| ★ E1 特效初始化失败 / 低性能设备 | 降级为 CSS 翻牌 + 淡入，人偶与收藏照给 |
| 两个客人扫同一张卡 | 各自独立发现、独立挑战彩蛋 |
| 服务端重启 | SQLite 恢复；已发现与彩蛋状态保留 |
| 外网断开 | 游戏期无影响（Lux3D 只在布置期需要外网） |
| 无 ticket 或 scope 不符请求资产 | 403 |
| GLB 加载失败 | 降级展示基础故事 + 原图，收藏仍记入 |
| 房间已结束 | 客人只读收藏册与终局回看 |
| 桌面浏览器打开 | 可完整通关 |
| 主人误点清空 | 二次确认 + 不可恢复提示 |

## 17. 埋点与成功指标

本地日志，不上传；不含答案明文、照片、任何图像。

`guest_join`（设备大类）、`card_scanned`（token、来源扫码/短码、耗时）、`egg1_played`（特效主题、是否重播、是否降级）、`egg1_replayed`（次数）、`egg_challenge_started`、`answer_submit`（正确、第几次、是否用提示、是否跳过）、`egg2_unlocked`（耗时）、`finale_reached`（触发条件、总时长）、`session_complete`（发现数/总数、彩蛋数/总数）、`network_error`（原因）。

## 18. 里程碑（5–8 天 / 2–3 人）

| 阶段 | 时间 | 目标 | 交付 |
|---|---|---|---|
| P0 · 链路验证 | D1 | 固定内网 IP → 手机扫码 → 浏览器打开局域网页；系统相机 / 微信两条路径都试 | 一张能跳转的二维码 |
| P1 · 骨架 | D1–D2 | 服务 + 主客两端 + 房间/昵称/localStorage 恢复 + 欢迎码 + 数据模型（含 level/finale 预留） | 扫码能进、跳回不丢进度 |
| P2 · **单人闭环（最重要节点）** | D2–D4 | 用**预置固定 GLB** 打通「扫码 → **E1 特效** → 人偶 → 收藏 → 彩蛋题 → E2 → 终局」；不答题也能通关 | 一位客人、一台手机完整通关 |
| P3 · 特效与关卡配置 | D4–D6 | E1 四主题 + 重播 + 降级；主人端关卡配置、题目自由录入、E2 内容、终局配置与预览 | 主人可独立配置一局 |
| P4 · B 线生成 | D5–D6 | 上传照片 → Lux3D 图生 3D → Blender 清理/剪影 → 落盘；现场生成 1 个当魔法时刻 | 生成链路 + 固定模型兜底 |
| P5 · 卡片与看板 | D6–D7 | token/短码/二维码、卡片 PDF、欢迎码、看板（含彩蛋与终局进度）、应急发现、清空数据 | 主人可独立完成布置并打印 |
| P6 · 真机与交付 | D7–D8 | iOS / 安卓 / 桌面各测；特效性能分档；网络异常态；demo 视频 / 报告书 | 提交物齐全 |

**砍刀线**

- D1 扫码链路没通（尤其微信内置）→ 立刻以「短码输入」为主入口，二维码只作辅助。
- **D4 E1 特效做不完 → 降级为 CSS 翻牌 + 淡入，但 E1 必现、扫码即见人偶这条不能砍。**
- D4 闭环没打通 → 砍到 3 个人偶、去掉 E2 与终局页、3D 只保留静态展示，优先保「扫码 → 特效 → 人偶 → 收藏」。
- D6 生成链路不稳 → 全部用预置/预生成人偶，魔法时刻用「预生成 + 播放生成过程录屏」兜底（v4 原策略）。
- 任何阶段都**不重新引入 AR / 摄像头**；不把多人关卡塞进 P0；不替主人限制题目难度。

- [ ] 断外网、桌面浏览器、二维码磨损输短码，都能完整通关

**Demo 视频脚本（60–75s）**

1. 0–6s：主人上传老照片 → 3D 人偶在预览里「长」出来（M1）。
2. 6–13s：主人给这张卡选「彩蛋题」、按自己心意写一道题、选星光特效；再给另一张卡选「纯发现」；顺手填好终局文案。
3. 13–20s：一键导出卡片 PDF → 打印 → 把剪影卡塞进书架第二层，门口贴欢迎码。
4. 20–27s：客人连 WiFi、扫欢迎码、首页「共 6 位在等你」。
5. 27–36s：找到卡 → 系统相机扫码 → **星光自卡面爆开、剪影溶解、3D 人偶浮起旋转 → 已收入收藏册**（M2，全程没答任何题）。
6. 36–40s：小朋友点「再放一次」，特效重播一遍（复玩点）。
7. 40–52s：点「再听听 TA 的故事」→ 答错一次（温柔反馈）→ 答对 → 金色收拢、隐藏故事与悄悄话浮现、收藏册落星（M3）。
8. 52–64s：继续找到其余卡（含一张只有彩蛋、没有题的卡）→ 集齐 → 主人配置的终局页 + 「拿这一页去找主人换贴纸」。
9. 64–72s：主人看板多人进度与彩蛋数跳动；落版「欢迎来到我的家 · 找到你就见到 TA」。

## 附录 A · 纯静态极简版（可选，不推荐作为主方案）

若想连 Node 服务都不跑：`index.html` + GLB/PNG + `config.js`，`python3 -m http.server 8080 --bind 0.0.0.0` 托管，二维码指向 `?d=<token>`，进度存 localStorage。

- **v3 下的额外代价**：E1 尚可跑（扫码即给），但 **E2 的 secret_ticket 机制无法成立**，隐藏故事与第二形态只能明文写进 `config.js`，F12 可直接看到；终局条件判定也只能前端做，无看板、无多人进度。
- **适用**：自己家玩 / 比赛 demo 快速验证 E1 特效观感；**不适合**作为正式产品形态。
- **折中建议**：保留极薄的 Node 服务（静态 + 判题 + SQLite），前端仍 100% 渲染，改动几十行，就能保住 E2 的「答对才听到」不被绕过。
