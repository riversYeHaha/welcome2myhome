## 0. 文档说明

### 0.1 本文解决什么问题

PRD v3 已经回答「做什么」与「为什么」，本文只回答「怎么实现、边界在哪、怎么验」：

| 问题 | 本文落点 |
|---|---|
| 系统由哪些进程/模块组成，部署成什么样 | 第 2 章 |
| 用什么技术栈，为什么不选别的 | 第 3 章 |
| 客人端与主人端各自怎么组织 | 第 4 章 |
| 扫码 → E1 → 答题 → E2 → 终局 的链路怎么落地 | 第 4～6、9 章 |
| 「扫码即爆特效、300ms 起播」怎么做到 | 第 6 章（核心） |
| 3D 人偶怎么生成、怎么清理、怎么压到 2MB | 第 7 章 |
| 数据怎么存、进度怎么不串号 | 第 8 章 |
| 防 F12 的两级 ticket 怎么签、怎么失效 | 第 9.4 节 |
| 安全、性能、兼容、测试、部署怎么做 | 第 10～13 章 |

### 0.2 对 PRD 的三处编号澄清（重要）

1. **PRD 第 18 章用 `P0～P6` 表示里程碑阶段，而第 10 章用 `P0/P1/P2` 表示功能优先级，两者同名不同义。** 本文与《开发计划》一律用 **S0～S7** 表示阶段（S = Stage），`P0/P1/P2` 只表示功能优先级。映射见《开发计划》第 3 章。
2. **PRD 4.4 写 `base_ticket`/`secret_ticket` 有效期 60s，但收藏册可能在数分钟后重新打开。** 本文定义：**ticket 是「一次资产请求」的凭证，不是会话凭证**；每次打开 `/d/:token` 或 `/api/collection` 时由服务端按当前进度重签，60s 只约束单次请求窗口（见 9.4）。
3. **PRD 7.3 要求 P2 多人类型在主人端「显示即将上线、不可点击」，而第 22 章开放问题 4 又在问「灰显还是隐藏」。** 本文按 7.3 执行：**灰显 + 不可选 + 服务端兜底降级为 `discovery`**。

### 0.3 与 PRD v2 工程结论的关系

v2 的工程结论全部有效，本文不重复论证，直接继承：

- 纯 HTTP 局域网，无 TLS、无证书、无云隧道、无 WebXR、无 `getUserMedia`；
- 二维码是 URL 深链，由手机系统相机 / 微信扫一扫识别，游戏页零摄像头；
- 前端 100% 渲染，服务端不生成任何画面、不接收摄像头帧；
- 主人电脑固定内网 IP，端口 8080；
- 服务端判题 + 答案加盐哈希保留，保护对象从「人偶」迁移为「E2 彩蛋」。

## 1. 目标、约束与工程指标

### 1.1 技术目标（从 PRD 成功标准翻译）

| PRD 目标 | 工程指标 | 验证方式 |
|---|---|---|
| 连 WiFi → 看见第一次彩蛋特效 ≤30s | 首次进入 ≤2 次点击、零安装零授权；扫码到 E1 首帧 ≤3s（含系统相机切浏览器） | 真机计时 |
| **零卡关 100%** | E1 内容服务端直出，JS 失败/判题超时/WebGL 失败均不阻塞人偶与收藏 | 故障注入 + 无 JS 测试 |
| E1 闭环 ≥95% | `/api/play/d/:token` 成功率 ≥99%；`/api/play/discover` 幂等且可重试 | 埋点 + 压测 |
| 首屏 / E1 起播 / 主模型 | <2s / <300ms / <3s（参考机：iPhone 12 / 中端安卓 / 300Mbps 局域网） | `performance.mark`。**口径**：扫码→页面打开 ≤3s；脚本执行→E1 首帧 <300ms；模型可见 <3s |
| 设备覆盖 | iOS Safari 16+、Android Chrome 100+、桌面 Chrome/Safari 完整通关 | 真机矩阵 |
| 并发 ≥8 台不串号 | 8 个 guest 并发扫码/答题/收藏互不干扰 | 并发脚本 |
| 断外网可玩 | 运行时零外网请求（生成期除外） | 断网演练 + 构建产物扫描 |

### 1.2 硬约束（不可协商）

| # | 约束 | 后果 |
|---|---|---|
| C1 | 不引入 HTTPS / 证书 / 隧道 | 客人零配置；也意味着 HTTP 明文，威胁模型见 10.1 |
| C2 | 游戏页零摄像头：代码中不得出现 `getUserMedia`、`navigator.xr` | CI 静态扫描拦截 |
| C3 | 不引第三方 CDN / 外链字体 / 外链动效库 | CSP `default-src 'self'`；DRACO 解码器、字体全部自托管 |
| C4 | 单进程、`npm start` 可起、数据全在 `./data` | 可整体拷走；主人电脑睡眠即停服 |
| C5 | 服务端只做四件事：静态托管、token/ticket 校验、E2 判题、数据存储 | 不做 SSR 动画、不转码视频、不做图像生成（生成期除外） |
| C6 | 一人一手机必须能走到终局 | 所有 P0 关卡类型不依赖他人进度 |

### 1.3 非目标（技术侧）

- 不做账号体系、不做多房间云端托管、不做跨家庭房间市场；
- 不做实时 PVP、不做 WebSocket 房间同步（看板用 SSE 足够）；
- 不做 PWA 离线安装（局域网 HTTP 下 Service Worker 不可用）；
- 不做服务端渲染首屏动画（只 SSR E1 的**内容与静态兜底**，动画由前端跑）；
- 不在 P0 实现多人关卡逻辑，只留枚举、字段与降级。

## 2. 总体架构

### 2.1 部署形态

```
┌──────────────────────────── 主人电脑 / NAS（固定内网 IP 192.168.1.50）────────────────────────────┐
│  单进程 Node.js :8080（纯 HTTP）                                                                  │
│                                                                                                   │
│  ┌─────────────┬──────────────────────────────┬──────────────────────────────────────────────┐  │
│  │ 静态/SSR     │ API（JSON）                   │ 运行时数据                                    │  │
│  │ /            │ /api/room*   /api/dolls*      │ SQLite  ./data/home.db                        │  │
│  │ /join        │ /api/gen/*   /api/cards.pdf   │ 资产    ./data/{photos,models,silhouettes}    │  │
│  │ /d/:token    │ /api/play/*  /api/assets/*    │ 导出    ./data/exports/*.pdf                  │  │
│  │ /collection  │ /api/finale/* /api/collection │ 日志    ./data/logs/*.jsonl                   │  │
│  │ /host（SPA） │ /api/board/:id/stream（SSE）  │ 密钥    ./data/secret.key（0600）             │  │
│  └─────────────┴──────────────────────────────┴──────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────────────────────────────────┘
        ▲ http://192.168.1.50:8080/                    ▲ http://192.168.1.50:8080/d/<token>?r=<room>
        │ 欢迎码（门口/餐桌）                            │ 每张实体卡的二维码
        │                                                │
   [ 客人手机 · 系统相机 / 微信扫一扫 ] ──「在浏览器中打开」──> 系统浏览器（Safari / Chrome）
   [ 主人电脑 · 本机 localhost:8080/host + PIN ] ──> 管理端与看板
```

### 2.2 分层与职责

| 层 | 组成 | 职责 | 不做什么 |
|---|---|---|---|
| 接入层 | Fastify 插件：静态、Cookie、速率限制、错误处理、CSP | 路由、校验、限流、统一错误 | 不写业务规则 |
| 应用层 | routes + services | 房间/卡/ticket/判题/终局/生成任务编排 | 不直接拼 SQL |
| 领域层 | `src/shared` 的枚举、状态机、守卫 | 关卡类型、进度状态迁移、终局条件纯函数 | 不依赖 HTTP |
| 数据层 | better-sqlite3 repos + 文件资产服务 | 参数化 SQL、事务、Range 流式返回 | 不缓存业务状态 |
| 前端 | `web/guest`（原生 TS）、`web/host`（React） | 演出、交互、本地会话 | 不持有答案、不判题 |

### 2.3 关键设计决策（ADR 摘要）

| # | 决策 | 理由 | 代价 / 备选 |
|---|---|---|---|
| ADR-1 | **单进程 Node + Fastify + SQLite**，不做前后端分离部署 | 一台家用电脑、零运维、`npm start` 即用；8 并发远低于 Fastify 能力 | 不能水平扩展（不需要）；备选 Express（更熟但缺内建 schema/限流） |
| ADR-2 | **客人卡片页 SSR**，E1 内容直出 HTML，JS 只做增强 | 保证「扫码即见」与 300ms 起播；JS 失败/慢网仍有人偶、故事、收藏按钮 | 模板简单字符串拼接即可，不用 React SSR |
| ADR-3 | **两级 HMAC ticket**（base/secret），无服务端会话表 | 无状态、可水平校验、过期即失效；60s 窗口足够拉 GLB | 不支持主动撤销（改密钥即可全局失效） |
| ADR-4 | **进度以 `(room, guest, doll)` 唯一键落 SQLite**，`discover` 幂等 upsert | 扫码新标签、刷新、重复点击都不重复计数 | 无 |
| ADR-5 | **答案只存 scrypt 加盐哈希**，单选提交「选项下标」由服务端映射文本再比对 | 前端拿不到正确下标，数据库泄露也难反推 | 单人维护同义词表 |
| ADR-6 | **特效引擎自研**（Canvas 2D + CSS + three.js + WebAudio），不引动效库 | 体积、离线、无 CDN；时间轴完全可控 | 需自己写粒子与缓动（约 600 行） |
| ADR-7 | **three.js 按需动态加载**，不阻塞 E1 首帧 | three 的 gzip 体积约 170KB，若阻塞则 300ms 必破 | 首帧用 CSS 剪影，模型就绪后再浮起 |
| ADR-8 | **看板用 SSE**，不用 WebSocket | 单向推送、原生 EventSource、断线自动重连 | 不能从看板下发指令（不需要） |
| ADR-9 | **生成任务内存队列 + 落库状态**，单并发 | 现场只生成 1～2 个，串行最稳，避免 GPU/API 额度打爆 | 进程重启丢队列，但任务状态落库可重试 |
| ADR-10 | **卡片 PDF 用 pdfkit 服务端生成**，中文字体自托管 | 不依赖浏览器打印、A4 拼版精确、可写入当前 LAN IP | 需带字体文件（OFL 授权） |

## 3. 技术选型

### 3.1 服务端

| 项 | 选型 | 版本基线 | 用途 / 理由 |
|---|---|---|---|
| 运行时 | Node.js LTS | 22.x | 与团队环境一致；`fetch`、`node:test` 内建 |
| 语言 | TypeScript | 5.x | 前后端共享类型，接口契约靠编译期兜底 |
| Web 框架 | Fastify | 5.x | JSON Schema 校验、`@fastify/rate-limit`、SSE 手写简单、性能好 |
| 数据库 | SQLite（better-sqlite3） | 11.x | 单文件、WAL、同步 API 简单；备份 = 拷文件 |
| 校验 | zod（应用层）+ Fastify schema（边界层） | 3.x / 4.x | 请求体与配置双重校验 |
| 日志 | pino（Fastify 内建） | 9.x | JSONL、低开销、可脱敏钩子 |
| 上传 | `@fastify/multipart` | 9.x | 限 10MB、流式落盘 |
| 图片预处理 | sharp | 0.33.x | 转 JPEG/WebP、缩到 1536、**自动剥离 EXIF**（隐私） |
| 二维码 | `qrcode` | 1.x | 服务端出 PNG/SVG，纠错等级 H，自托管 |
| PDF | `pdfkit` + fontkit | 0.15.x | A4 拼版、矢量文字、嵌入中文子集 |
| 3D 压缩 | `@gltf-transform/cli` | 4.x | Draco 压缩与体积检查（构建/生成阶段调用） |
| 加密 | Node `crypto`（scrypt / HMAC / randomBytes） | 内建 | 不引第三方加密库 |
| 测试 | Vitest + Playwright | 2.x / 1.4x | 单测/集成 + 真浏览器 E2E |

### 3.2 前端

| 项 | 客人端 | 主人端 | 理由 |
|---|---|---|---|
| 框架 | **原生 TypeScript**（无框架） | **React 18 + Vite** | 客人端要极限压首屏；主人端表单多，React 省人天 |
| 构建 | Vite 6（MPA 多入口） | 同左 | 一个仓库、两条产物、共享 shared 类型 |
| 3D | three.js（r17x）+ GLTFLoader + DRACOLoader | 同左（预览/展柜） | 控制力强于 `<model-viewer>`；decoder 自托管 |
| 特效 | Canvas 2D + CSS Transform + WebAudio | — | 无第三方动效库、无音频文件 |
| 状态 | 事件驱动 + 少量 localStorage | React state + 轮询/SSE | 不引 Redux |
| 请求 | `fetch` 封装（超时、重试、错误码映射） | 同左 | 无 axios |
| 样式 | 原生 CSS（CSS 变量 + `prefers-reduced-motion`） | 同左 + CSS Modules | 不引 UI 库，避免体积与风格失控 |

### 3.3 生成侧

| 项 | 选型 | 说明 |
|---|---|---|
| 图生 3D | Aholo Lux3D（赛事指定） | 通过 REST API 调用；密钥走环境变量；**API 不可用时降级为「本机上传 GLB」** |
| 风格化生图（可选） | 可配置（Flux / 即梦 / 万相任选其一） | 只用于统一风格；不配置则跳过，直接用原图 |
| 模型清理 | Blender 4.x headless（`--background --python`） | 应用变换、重算法线、减面、原点归脚底、导出 GLB |
| 剪影 | Blender 正交相机 + 纯黑自发光 + 透明底渲染 PNG | 与卡面剪影、页面占位共用同一张 |
| 压缩 | glTF-Transform（Draco） | 目标 <2MB、<1.5 万三角面、贴图 ≤1024 |
| 兜底 | 预置 6 套 GLB + 剪影 | A 线先跑通玩法；生成失败/超时直接落预置 |

### 3.4 不选的方案（记录理由，避免返工）

| 备选 | 否决理由 |
|---|---|
| Next.js / Nuxt（SSR 框架） | 本项目只有一个需要 SSR 的卡片页，框架体积与构建复杂度得不偿失 |
| WebSocket / Socket.IO 实时同步 | 看板只需单向刷新；SSE 原生重连，少一个依赖 |
| `<model-viewer>` | 体积与可定制性不如直接 three.js；且需自托管（无 CDN 时优势消失） |
| 纯静态版（PRD 附录 A） | E2 的 `secret_ticket` 不成立，答案可被 F12 直接看穿；仅作赛前观感验证 |
| 前端判题 + 加密答案 | 任何下发到客户端的答案都可被破解；PRD 明确服务端判题 |
| PWA / Service Worker | `http://192.168.x.x` 不是安全上下文，SW 不可用 |
| 把 GLB 存 IndexedDB | 局域网重拉 1.5MB 只需几十毫秒，缓存收益低、清理复杂 |

### 3.5 版本锁定与供应链

- 全部依赖写入 `package-lock.json`（npm ci 安装），不用 `^` 漂移关键包；
- 构建产物扫描：不得出现 `http://` / `https://` 外部域名（除注释白名单）；
- `npm audit` 作为 D1 检查项，不阻塞开发但记录；
- 字体：`Noto Sans SC`（OFL 1.1）子集随仓库自带，PDF 与页面共用，禁止外链 Google Fonts。

## 4. 前端架构

### 4.1 路由与页面清单

| 路由 | 渲染方式 | 使用者 | 说明 |
|---|---|---|---|
| `/` | SSR 静态页 + JS 增强 | 客人 | 欢迎页：房间标题、已等待人偶数、规则、昵称入口、网络自检提示 |
| `/join?r=<room_code>&next=<path>` | SSR 表单 | 客人 | 填昵称 → `POST /api/guests/join` → 跳回 `next` |
| `/d/:token?r=<room_code>` | **SSR + E1 增强** | 客人 | 卡片页：服务端校验 token 后直出 E1 内容（名字/剪影/故事/base ticket），前端播特效。SSR 路由内部直接调用领域服务，不绕自己的 HTTP API |
| `/d?code=<short>` | SSR 表单 / 前端提交 | 客人 | 短码入口；提交后等价命中卡片 |
| `/collection` | SSR 壳 + JS 拉数据 | 客人 | 收藏册、彩蛋角标、终局回看入口 |
| `/finale` | SSR 壳 + JS 拉数据 | 客人 | 条件未达成显示进度；达成显示主人配置内容 |
| `/host/*` | SPA（React） | 主人 | 配置向导、人偶、关卡、终局、卡片导出、看板、预览 |
| `/error/:code` | SSR | 双方 | 房间未开、卡不属于本局、网络错误等友好页 |

> 所有客人页面**不依赖 SPA 路由切换**：每次扫码都是整页导航，因此会话恢复必须走 localStorage，不能假设内存状态存活。

### 4.2 客人端模块划分

```
src/web/guest/
├─ boot.ts            # 读取 data-* 引导数据、注册全局错误兜底
├─ session.ts         # guest_token / nickname / room_code 的读写、失效清理
├─ api.ts             # fetch 封装：超时、重试（仅 GET）、错误码 → 文案
├─ effect/
│  ├─ engine.ts       # 状态机 + 时间轴调度（唯一时钟）
│  ├─ particles.ts    # Canvas 2D 粒子（四主题）
│  ├─ audio.ts        # WebAudio 合成音（三音/收拢/翻页）
│  ├─ flip.ts         # 翻牌/白光/剪影溶解的 CSS 层控制
│  └─ fallback.ts     # 降级链：静帧、CSS 版、无 JS 版
├─ viewer/doll.ts     # three.js 场景、GLB 加载、旋转/缩放、销毁
├─ quiz.ts            # 答题入口、提示、答错文案、重试/跳过
├─ egg2.ts            # E2 演出（金色收拢 + 故事逐行 + 星标）
├─ collection.ts      # 收藏册渲染、角标、终局入口
├─ finale.ts          # 终局页
└─ telemetry.ts       # 埋点批量上报（sendBeacon）
```

**职责边界**：`effect/*` 不直接调 API；`quiz.ts` 不直接操作 three.js；所有内容数据由 SSR 注入的引导 JSON（`data-boot` 属性）提供，避免二次请求。

### 4.3 主人端模块划分

```
src/web/host/
├─ main.tsx
├─ api.ts                 # 带 CSRF 头的 fetch
├─ pages/
│  ├─ Setup.tsx           # 首次运行：PIN、房间、固定 IP 自检
│  ├─ Room.tsx            # 房间开关、看板入口
│  ├─ DollList.tsx        # 人偶列表、生成进度、换模型
│  ├─ DollEditor.tsx      # 基础谜底 + 关卡（level_type / 题目 / E1 / E2）
│  ├─ FinaleEditor.tsx    # 终局条件与内容
│  ├─ Cards.tsx           # token / 短码 / 二维码 / 导出 PDF / 欢迎码

└─ components/            # 表单控件、颜色/主题选择、二次确认
```

- 表单字段全部由 `src/shared/levels.ts` 的枚举与 zod schema 生成校验，前后端共用，避免「前端能填、后端拒收」。
- P2 多人类型（`race`/`coop`/`duo_scan`/`timed`）在下拉框中**灰显 + 「即将上线」**，不可提交；服务端对**交互式提交**返回 422 `LEVEL_TYPE_NOT_AVAILABLE`，对**已存/导入的配置**按 `discovery` 降级（PRD 16），两条路径都保证单人可通。

### 4.4 会话与本地存储

| Key | 内容 | 生命周期 | 说明 |
|---|---|---|---|
| `wtm_guest`（Cookie） | 同 guest_token，`HttpOnly; SameSite=Lax; Path=/` | 30 天 | **SSR 导航读取身份的唯一途径**（导航请求带不了 Authorization 头）；接口也接受 cookie |
| `wtm.v1.guest_token` | 服务端签发的 HMAC token | 30 天 | 前端 API 用 `Authorization: Bearer`；cookie 被清后的恢复来源 |
| `wtm.v1.guest_id` | `g_` + 12 位 base62 | 30 天 | 仅展示/调试用，服务端以 token 为准 |
| `wtm.v1.nickname` | 昵称 | 30 天 | 恢复时免二次输入 |
| `wtm.v1.room_code` | 房间码 | 30 天 | 扫码深链缺 `r` 时兜底 |
| `wtm.v1.replay_count` | 重播次数 | 会话 | 仅埋点用 |

**恢复规则**：

0. 服务端渲染前先读 `wtm_guest` cookie 确定 guest；前端 `session.load()` 再读 localStorage 用于 API 调用与重建；
1. 打开任意客人页面 → `session.load()`；
2. `guest_token` 存在但服务端 401（过期/密钥轮换）→ 清除并跳 `/join?r=<room_code>&next=<当前 path>`；
3. cookie 与 localStorage 均缺失且当前是 `/d/:token` → 跳 join，**保留 next**，填完昵称后回到原卡片，E1 正常播（多一步，但不丢进度）；
4. localStorage 不可用（隐私模式）→ 退化为内存会话，页面顶部提示「本次进度仅本页有效」；不阻塞 E1。

### 4.5 加载策略与性能预算

**关键路径（卡片页）**：

```
HTML（SSR，含 E1 文案与剪影 <img>）
 ├─ 内联 critical CSS（≤8KB）
 ├─ 内联 boot 脚本（≤3KB，非阻塞）
 ├─ modulepreload effect 入口
 └─ DOMContentLoaded → 立即启动时间轴（不等 three/GLB）
       └─ 并行：动态 import three + fetch GLB（带 ticket）
```

| 产物 | 预算（gzip） | 策略 |
|---|---|---|
| HTML（卡片页） | ≤ 12KB | SSR 直出，无客户端模板 |
| critical CSS | ≤ 8KB 内联 | 只含首屏与特效关键帧 |
| effect 入口 JS | ≤ 18KB | 粒子/音效/时间轴 |
| three.js chunk | ≤ 180KB | 动态 import，不阻塞首帧 |
| DRACO 解码器 | 自托管 wasm ~150KB | 仅压缩模型触发；`Cache-Control: immutable` |
| GLB | ≤ 2MB | 预加载 + 进度条；失败降级原图 |
| 字体 | 页面用系统字体栈 | 不加载 Web 字体；PDF 才嵌字体 |

**规则**：

- 首帧前禁止同步 XHR、禁止等待模型、禁止等待埋点；
- 页面内不引用任何外部域名；预加载用同源相对路径；
- 图片：剪影 PNG 生成两档（页面 512px / PDF 1024px），`loading="eager"` + `fetchpriority="high"`；
- 扫码进入的是**新标签页**，不能假设前一页面的内存缓存，因此 GLB 重新拉取是常态（局域网可接受）。

### 4.6 错误与降级 UI

| 场景 | 表现 |
|---|---|
| 房间非 live / 已结束 | SSR 错误页：状态说明 + 收藏册入口（已结束只读） |
| token 不属于本局 | 「这张卡不属于本局」+ 返回首页 / 输短码 |
| 短码错误 | 原位提示，不刷新页面；3 次后提示检查卡片 |
| 网络断开 | 顶部横幅「已断开主人家的 WiFi」+ 重试按钮；不白屏 |
| API 5xx | 内容照常展示（SSR 已有），非关键操作给重试提示 |
| JS 报错 | `window.onerror` 兜底：移除动画层、显示静帧 + 「已收入收藏册」 |
| 无 JS | SSR 页面含名字/故事/剪影 + 「收藏」表单（`<form method=post>` 提交 discover），E1 静态内容仍可读 |

### 5.2 请求管线

```
请求
 → 安全头（CSP / X-Content-Type-Options / Referrer-Policy）
 → 静态文件（命中即返回；无目录遍历）
 → 路由匹配
 → 鉴权（host 会话 / guest token / card token，按路由声明）
 → 速率限制（按主体：IP / guest / 组合键）
 → 请求体解析与 zod 校验（体积上限）
 → handler
 → 统一错误映射（AppError → HTTP + code + 用户文案）
 → 访问日志（路径脱敏：不记录 query 中的 ticket/token）
```

### 5.3 认证与授权

**主人端**

- 首次启动生成 4–8 位 PIN（主人设置），存 `scrypt` 哈希；
- `POST /api/host/login` → 校验 → 下发 `wtm_host` cookie：`HttpOnly; SameSite=Strict; Path=/`，内容为 HMAC 签名的 `{sid, exp, pinv}`（12h）；
- **默认只允许本机**：`request.socket.remoteAddress` 非回环则 403 `HOST_LOCAL_ONLY`（配置 `host.allowLanAdmin=true` 可放开，用于手机看看板）；
- 修改 PIN 时递增 `pinv`，使所有旧会话失效；
- 变更类请求校验 `Origin` 与自定义头 `X-WTM-CSRF`（值来自登录响应），双保险。

**客人端**

- `POST /api/guests/join`：校验 `room_code` 属于 live 房间 → 生成 `guest_id`（随机 128bit）→ 签发 `guest_token`（HMAC，30 天）→ **同时写入 HttpOnly cookie `wtm_guest` 并在响应体返回 token**；
- **SSR 卡片页靠 cookie 认证**（浏览器导航无法带 `Authorization` 头）；XHR/fetch 用 `Authorization: Bearer`，服务端两者都接受，cookie 优先；
- cookie 被清但 localStorage 仍有 token 时，前端 boot 调 `POST /api/guests/resume` 重建 cookie 后刷新；
- 所有 `/api/play/*`、`/api/collection/*`、`/api/finale/*` 必须已认证（Bearer 或 cookie）；
- 服务端从 token 解析 `room_id` 与 `guest_id`，**绝不信任请求体里的 guest_id / room_id**；
- 卡片 token 只在 URL 中出现一次（`/d/:token`），服务端解析后即把 `doll_id` 放进响应，前端后续用 `doll_id`。

**卡片 token**

- 10 位 base62（62^10 ≈ 8.4×10^17），随机生成，不落顺序号；
- 每个 token 唯一索引，另可生成 `token_backup` 指向同一人偶；
- 校验链：token 存在 → 房间 live → 不合法统一返回「这张卡不属于本局」，不区分具体原因（防探测）。

### 5.4 判题服务（仅保护 E2）

**输入**：`{doll_id, choice_index? , answer_text?}` + guest token。

**进入答题**：前端点「再听听」→ `POST /api/play/egg/start` 幂等置 `egg_answering`（看板「彩蛋挑战」计数）；答错时 `answer` 事务内 `attempts+1`，状态保持 `egg_answering`，不锁定。

**流程**：

1. 防爆破限流：同一 `(guest, doll)` 30s 内最多 6 次（突发桶，正常人类重试不会触发，**不构成冷却**）；同一 guest 每分钟 30 次；同一 IP 每分钟 300 次（进程内令牌桶，单进程足够）；
2. 读取该卡的 `riddle`；若 `egg_enabled=false` → 直接 `{correct:false, code:"EGG_DISABLED"}`（正常前端不会出现）；
3. 归一化答案（见 5.4.1）；
4. 用 `scrypt` 校验 `answer_hash`，并逐条比对 `synonyms`（同义词在写入时已归一化）；
5. 判定：
   - **正确** → 事务内写 `progress.state = egg_unlocked` + `egg_unlocked_at`（幂等：已是 `egg_unlocked` 则跳过写）→ 签 `secret_ticket` → 返回 `{correct:true, secret_ticket, secret:{...}, star:true}`；
   - **错误** → 返回 `{correct:false, wrong_text, hint?（主人允许时）, attempts, max_attempts, can_retry:true, can_skip:true}`，**永不返回锁定/冷却字段**；
6. 判题异常（scrypt 抛错、DB 忙）→ 返回 `JUDGE_UNAVAILABLE`，前端提示「故事稍后再来」，**不改动进度状态**。

**5.4.1 归一化规则**（`lib/normalize.ts`）

```
NFKC 兼容分解 → 全角转半角（NFKC 已覆盖）→ 去首尾空白
→ 英文转小写 → 去除空白与常见标点（，。！？、；：""''（）【】…—·,.!?;:'"()[]）
→ 连续空白折叠 → 长度限制 100 字符
```

- 单选：前端提交 `choice_index`，服务端用自己保存的 `options[index]` 取文本再归一化比对；**选项顺序与正确项下标永不下发**；
- 简答：只比对归一的文本与同义词表；不做模糊匹配（避免「差不多对」的歧义），由主人自己维护同义词；
- `max_attempts`：**只用于文案与主人端统计**，`0` 表示不限；即使次数用尽，接口仍返回可重试，前端仍显示「再试一次」。

### 5.5 终局判定

触发条件（PRD 9.2）实现为纯函数：

```ts
type FinaleTrigger =
  | { type: 'all_collected'; value: null }
  | { type: 'count_gte'; value: number }
  | { type: 'all_eggs'; value: null }
  | { type: 'manual'; value: null }
```

- `all_collected`：已完成 discover 的人偶数 == 房间人偶数（**不看 E2**）；
- `count_gte`：已完成 discover 的人偶数 ≥ N（N 由主人填，校验 1..总数）；
- `all_eggs`：`all_collected` 且所有 `egg_enabled=true` 的卡均已 `egg_unlocked`；若没有任何卡启用彩蛋题，视为等价 `all_collected`，主人端保存时给出警告；
- `manual`：主人点击 `POST /api/room/:id/finale/open` 置 `finale_open_at`，之后所有客人查询即达成（已开局的客人刷新后可见）。

判定时机：每次 `discover` / `answer` 成功后；`GET /api/finale/:room_id` 时再算一次并幂等写 `finale_reached_at`。单人模式下**条件不读取他人进度**（`count_gte` 的计数也只来自本 guest）。

### 5.6 SSE 看板

- `GET /api/board/:room_id/stream`，`Content-Type: text/event-stream`；
- 心跳 15s；事件类型：`progress`（某客人某卡变化）、`guest_online`、`finale`；
- 服务端只在数据变更时广播，前端每收到事件拉一次聚合接口（避免推送大对象）；
- 连接上限 8（主人 + 预览多开）；房间结束后 5s 主动关闭；
- 断线由 EventSource 自动重连，前端显示「离线」角标。

### 5.7 生成任务队列

```
POST /api/dolls（multipart 照片）
  → 落盘 data/photos/<doll>_src.jpg（sharp 剥离 EXIF、限 1536px）
  → 建 doll（gen_status=queued），返回 202 {doll_id, task_id}
  → 内存队列（并发 1）执行：
     [1] preprocess    （sharp，10%）
     [2] style         （可选生图，20%，未配置则跳过）
     [3] lux3d         （图生 3D，轮询，20→70%）
     [4] download      （GLB 落 data/models/<doll>_raw.glb，75%）
     [5] blender       （清理/减面/原点/剪影，85%）
     [6] draco         （压缩校验，95%）
     [7] verify        （体积/面数/贴图检查，100%）
  → 任一步失败：记录 error，落预置模型（fallback=true），主人端可重试或手动上传
GET /api/gen/:task_id → {stage, percent, status, error, fallback_used}
```

- 任务状态同时写 `gen_tasks` 表，进程重启后可把 `running` 重置为 `queued` 再跑；
- 单任务硬超时 300s（Lux3D 180s + Blender 90s + 余量）；
- **现场只生成 1 个**，其余用预置/预生成；游戏期不触发任何生成。

### 5.8 静态资源与 Range

- `/api/assets/:doll/:kind`（GLB / 原图）：经 ticket 校验后流式返回，支持 `Range`、`ETag`、`Cache-Control: private, max-age=86400`；
- `/assets/silhouettes/*.png`：公开（占位图不泄密），`Cache-Control: public, max-age=604800`；
- `/cards/*.png`：公开二维码 PNG（不含答案），长缓存；
- 所有静态路径做白名单前缀 + `path.resolve` 越界检查；
- 不使用 `send` 的目录列表；`.glb` MIME 显式 `model/gltf-binary`。

### 5.9 错误模型

```ts
interface ApiError { error: { code: string; message: string; retryable?: boolean } }
```

- 业务错误码见附录 F；HTTP 状态：400/401/403/404/409/410/413/422/429/500/503；
- 用户可见文案与内部 code 分离：客人看到「这张卡不属于本局」，日志里才记具体原因；
- 500 不暴露堆栈；`X-Request-Id` 方便现场排查。

### 5.10 日志与埋点

- 访问日志：`time, req_id, method, path（脱敏）, status, ms, ip_hash`；
- 业务事件表 `events`：`guest_join / card_scanned / egg1_played / egg1_replayed / egg_challenge_started / answer_submit / egg2_unlocked / finale_reached / session_complete / network_error`（PRD 17）；
- **脱敏红线**：不记录答案明文、不记录照片路径、不记录完整 ticket/token、不记录昵称之外的个人信息；
- 日志文件按天切分，保留 14 天；`GET /api/host/logs/export`（P1）导出 JSONL 供复盘。

## 6. E1 / E2 特效引擎（核心）

### 6.1 时间轴（与 PRD 8.1 / 8.2 对齐）

| 时刻 | 视觉 | 音频 | 实现层 |
|---|---|---|---|
| 0–300ms | 卡片翻牌展开（rotateY 0→-90°→0° 的错觉用两段）+ 一道白光从左到右扫过 + 轻震（`navigator.vibrate(20)`，iOS 忽略） | 无 | CSS transform + 伪元素渐变 |
| 300–1000ms | 粒子自卡面中心向外爆散（主题：星光/纸屑/泡泡/火花） | 上行三音（C5-E5-G5，各 110ms，三角波 + 包络） | Canvas 2D + WebAudio |
| 1000–2000ms | 灰剪影自下而上溶解（`mask-image` 渐变 + 位移）→ 3D 人偶浮起（y +40px、缩放 0.92→1、缓慢自转 6°/s） | 轻微 whoosh（噪声 + 低通扫频） | CSS mask + three.js |
| 2000–2600ms | 名字 + 一句话淡入；底部「已收入收藏册」滑入 | 收册翻页音 | DOM + CSS |
| 2600ms+ | 停驻人偶视图；出现「再放一次」与（若有题）「再听听 TA 的故事」 | — | DOM |
| E2 | 答对：对勾 → 金色光边**向内收拢** → 第二形态/隐藏故事逐行 → 悄悄话气泡 → 星标落下 | 柔和收拢音 + 星标叮 | CSS conic-gradient 边框 + DOM + 可选 three 换模 |

**视觉语言**：E1 = 向外爆开（暖亮），E2 = 向内收拢（金色）。两者色温、方向、音色都不同，确保小朋友一眼区分（PRD 14.2）。

### 6.2 分层渲染

| 层 | 技术 | 内容 | 是否阻塞 E1 |
|---|---|---|---|
| L0 内容层 | SSR HTML | 名字、剪影 `<img>`、一句话、故事、按钮 | 否（已是首屏） |
| L1 装饰层 | CSS transform/opacity/mask | 翻牌、白光、溶解、边框收拢、星标 | 否 |
| L2 粒子层 | Canvas 2D（`pointer-events:none`，全屏 fixed） | 粒子爆散 | 否（可跳过） |
| L3 模型层 | three.js（独立 canvas，位于内容层之后） | 3D 人偶、旋转、缩放、第二形态 | 否（模型就绪才浮起） |
| L4 音频层 | WebAudio（无文件） | 三音、whoosh、收拢音、翻页 | 否（失败静音） |

**统一时钟**：`engine.ts` 用 `performance.now()` 作唯一时间源，所有子层由同一个 rAF 循环驱动；CSS 动画通过 `animation-delay` 对齐到同一 t0，避免「各播各的」。

### 6.3 状态机

```
boot ──> flip ──> burst ──> dissolve ──> reveal ──> settle
  │        │         │           │            │
  └────────┴─────────┴───────────┴────────────┴──> degraded（任一步失败）
                                                      │
settle ──[再放一次]──> burst（重置状态，保留已加载模型）
settle ──[E2 入口]──> egg2_in
egg2_in ──> egg2_out ──> settled
任意状态 ──[跳过]──> settle（内容已给，不可逆）
```

- 所有状态迁移幂等；重复 `play()` 被忽略；
- 页面不可见（`visibilitychange`）→ 暂停 rAF、暂停音频；回到前台按剩余时间继续或直接结算到 `settle`（超 5s 不可见则直接 settle，避免回来看到半截）；
- 组件卸载（SPA 内跳转）→ `dispose()`：停 rAF、断 audio、`renderer.dispose()`、纹理/几何体释放、`canvas` 移除。

### 6.4 粒子系统

| 主题 | 形状 | 主色 | 运动 | 附加 |
|---|---|---|---|---|
| `starlight` 星光 | 四角星（两条交叉细线 + 光晕） | 暖白 / 金 | 径向爆散 + 轻微重力 + 闪烁 | 亮度衰减 |
| `confetti` 纸屑 | 矩形条 | 主人选色（默认红黄蓝绿） | 爆散 + 旋转 + 重力下落 | 翻转 |
| `bubbles` 泡泡 | 圆形描边 | 半透明青/粉 | 缓慢上浮 + 左右摆动 | 高光点 |
| `sparks` 火花 | 短线段（拖尾） | 橙 / 金 | 快速径向 + 摩擦减速 | 加色混合 |

- 数量分档：**120 / 60 / 24**（高/中/低），低档仅翻牌 + 淡入；
- 分档判定顺序：`prefers-reduced-motion` → 低（直接无粒子）> `navigator.hardwareConcurrency ≤ 4` 或 `deviceMemory ≤ 3` → 低 > 首帧 500ms 采样 `<40fps` → 降一档 > 否则高档；
- 粒子贴图：**运行时用 Canvas 程序化生成**（星形/圆/矩形），不加载图片，首帧零网络；
- 单帧上限 120 个粒子、生命周期 ≤1.2s，`globalCompositeOperation='lighter'` 仅 sparks 使用（省 GPU）。

### 6.5 音效合成（WebAudio）

| 音效 | 合成方式 | 时长 |
|---|---|---|
| E1 上行三音 | 三角波 C5(523.25)/E5(659.25)/G5(783.99)，每音 110ms，ADSR 快起慢落 | 330ms |
| E1 whoosh | 白噪声 buffer + 带通从 1800→400Hz 扫频，增益包络 | 900ms |
| 收册翻页 | 短噪声脉冲 + 高通，双声 | 120ms |
| E2 收拢 | 正弦 G5→C5 下滑 + 轻混响（Convolver 用程序化脉冲） | 700ms |
| E2 星标 | 正弦 C6 + 高频泛音，短衰减 | 200ms |

**自动播放策略（必须写进实现）**：浏览器要求用户手势后才能出声。扫码打开的新页面通常**没有手势**，因此：

1. 视觉序列**不等待**音频，立即起播；
2. `AudioContext` 在首次 `pointerdown/keydown` 时 `resume()`，并补播当前阶段的音（若已过 1s 则只播收册音）；
3. 若 `audioCtx.state === 'suspended'`，右下角显示「🔊 点我开声」小胶囊（不遮挡内容），点击后重播本段音效；
4. 主人关闭「音效」时完全不创建 AudioContext；
5. 音频初始化失败静默降级，**绝不弹错**。

### 6.6 降级链与 300ms 看门狗

```
启动
 ├─ SSR 内容已可见（保证零白屏）
 ├─ reduced-motion? → 直接 settle（静帧 + 名字，无粒子）
 ├─ WebGL 可用? ──否──> CSS 翻牌 + 淡入（无 3D，人偶用剪影 PNG）
 │        └─ 是 → 立即播 L1/L2；并行加载 three + GLB
 ├─ GLB 失败/超时(3s) → 保持剪影静帧 + 显示基础故事与原图（收藏照常）
 └─ 首帧看门狗：t0 后 300ms 内未画出第一帧（rAF 未回调或 JS 异常）
        → 移除动画层，直接显示 SSR 静帧 + 按钮（内容不丢）
```

- 看门狗用 `performance.now()` 判断：第一次 rAF 回调里若 `now - t0 > 300`，跳过粒子准备，直接进入 `dissolve` 的 CSS 版；
- 另设 `setTimeout(300)` 兜底（主线程被长任务阻塞时，定时器会在空闲后触发，仍显示静帧）；
- 降级不改变业务：`discover` 上报照常，收藏照常。

### 6.7 重播（P0 复玩点）

- 「再放一次」按钮在 `settle` 后出现；点击 → 重置粒子与 CSS 动画，保留已加载模型，重跑 `burst → dissolve → reveal`；
- 前端限流：同一按钮 800ms 内只响应一次；`egg1_replayed` 只记次数（不记逐帧）；
- 重播**不重复写** discover（幂等接口本身也保证）；
- 可无限重播，但连续 10 次后粒子降一档（保护低端机）。

### 6.8 与 GLB 加载解耦

- 特效不等模型：`burst` 与 `dissolve` 用剪影 PNG 完成，模型就绪后再「浮起」；
- 模型加载 3s 未完成：先用剪影静帧 + 「正在唤醒 TA…」进度点；完成后无缝替换（`opacity` 交叉淡入）；
- 模型加载失败：保留剪影 + 基础故事 + 原图（PRD 16），收藏照常；
- `preload`：服务端在 HTML 中输出 `<link rel="preload" as="fetch" href="/api/assets/...?ticket=...">`，浏览器与特效并行拉取；`fetch` 优先级 `high`。

### 6.9 度量

| 标记 | 含义 |
|---|---|
| `e1:boot` | 页面脚本开始执行 |
| `e1:firstframe` | 第一帧特效绘制完成（**核心指标 <300ms**） |
| `e1:model` | 3D 模型首帧可见（<3s） |
| `e1:settle` | 停在人偶视图（≈2.6s） |
| `e2:start` / `e2:done` | E2 演出起止（1.5–2.5s） |
| `e1:degraded` | 降级原因（webgl / timeout / reduced-motion / error） |

埋点随 `egg1_played` 上报：主题、是否降级、首帧耗时、是否重播。

## 7. 3D 资产管线（B 线）

### 7.1 总体流程

```
原始照片（≤10MB, jpg/png/webp）
  →[A] sharp 预处理：EXIF 剥离、EXIF 旋转矫正、最长边 1536、转 JPEG q88
  →[B]（可选）风格化生图：统一成 Q 版/黏土风（失败则跳过）
  →[C] Lux3D 图生 3D：轮询任务，取回 GLB（带 PBR）
  →[D] Blender headless 清理：应用变换/重算法线/减面/原点归脚底/朝 +Z
  →[E] 剪影渲染：正交相机 + 纯黑自发光 + 透明背景 → 1024px PNG
  →[F] glTF-Transform Draco 压缩 → 体积/面数/贴图校验
  →[G] 落盘 data/models/<doll>.glb + data/silhouettes/<doll>.png
  →[H] 写 assets 表、更新 doll 状态、主人端预览
```

- 任何一步失败 → 标记 `fallback=preset`，复制预置 GLB/剪影，主人端提示可重试；
- 每步写 `gen_tasks.stage` 与进度，前端轮询展示；
- **预生成优先**：D1 用预置人偶打通玩法；B 线只在 D5–D6 接入，现场只演示 1 个。

### 7.2 Lux3D 适配层

```ts
interface Gen3DProvider {
  submit(input: { imagePath: string; prompt?: string; style?: string }): Promise<{ jobId: string }>
  poll(jobId: string): Promise<{ status: 'pending'|'running'|'done'|'failed'; modelUrl?: string; error?: string }>
}
```

- 实现 `Lux3DProvider`（REST + 轮询）与 `ManualProvider`（只接收本机上传的 GLB，用于 API 不可用时）；
- 密钥只从环境变量 `LUX3D_API_KEY` 读取，**不写进仓库与日志**；
- 配置 `config/default.json`（+ `config/local.json`）的 `generation` 段：provider、endpoint、model/version、提示词模板、超时、重试次数（见 13.3）；
- 生成期需要外网，**游戏期完全不需要**（PRD 1.5）。

### 7.3 Blender 清理脚本规格（`scripts/blender/clean.py`）

| 步骤 | 参数 / 做法 |
|---|---|
| 导入 | `bpy.ops.import_scene.gltf(filepath=raw)` |
| 清理 | 应用全部变换；合并重复顶点（0.0001）；重算法线；删除孤立点；修非流形（可选） |
| 减面 | Decimate（collapse）到 ≤15,000 tris；若仍超，先 Remesh 再 Decimate |
| 规范 | 单位 1m；原点在脚底中心；朝向统一 +Z 或 +Y（以相机为准）；整体高度归一到 0.35m（人偶尺寸） |
| 材质 | 保留 PBR；贴图 ≤1024；无法识别材质时用纯色兜底 |
| 导出 GLB | `export_format='GLB'`，不导出相机/灯光/动画（MVP 无骨骼） |
| 剪影 | 复制模型 → 新场景 → 正交相机（正对 +Z，正交尺度 0.5）→ 材质替换为纯黑 Emission → `film_transparent=True` → 渲染 1024×1024 PNG（RGBA） |
| 退出码 | 成功 0、校验失败 2、异常 1；stdout 输出 JSON 摘要供服务端解析 |

- 本机无 Blender 时：`config.generation.blenderEnabled=false`，跳过 D/E，用 Lux3D 原始 GLB + 前端兜底剪影（从 GLB 截一张图不可行，故直接用占位剪影模板）；
- Blender 版本锁定 4.x，路径写配置（`/Applications/Blender.app/Contents/MacOS/Blender`）。

### 7.4 资产规范与校验

| 项 | 阈值 | 校验点 |
|---|---|---|
| GLB 体积 | < 2MB | 生成后 + 导出 PDF 前 |
| 三角面 | < 1.5 万 | Blender 脚本输出 |
| 贴图 | ≤ 1024×1024 | glTF-Transform inspect |
| Draco | 开启 | 压缩后必须能被自托管 decoder 解码 |
| 剪影 | 1024×1024 RGBA，透明底，纯黑 | 页面 512 缩略 |
| 朝向 | 正面朝相机，脚底在原点 | 主人端预览可见 |
| 命名 | `d_001.glb` / `d_001_silhouette.png` | 正则校验，禁路径分隔符 |

### 7.5 预置与缓存兜底

- 仓库自带 `assets/presets/` 6 套人偶（GLB + 剪影 + 示例故事），`scripts/seed.ts` 首次启动灌入；

### 7.6 资产生命周期

| 阶段 | 位置 | 清理策略 |

## 8. 数据模型与存储

### 8.1 设计原则

1. **SQLite 单文件 + WAL**：一屋子 8 台设备、只读多写少，足够；备份就是拷 `data/home.db`。
2. **JSON 字段存配置，关系字段存状态**：`level/riddle/secret/finale` 用 JSON 文本（一次成型、避免频繁改表），`progress` 用关系表（唯一键约束保证不串号）。
3. **所有时间存 UTC ISO8601**，展示时转 `Asia/Shanghai`。
4. **答案永不落明文**：只存 `answer_hash` 与归一化后的 `synonyms`。
5. **枚举一次预留到位**：`level_type` 支持 5 种、`game_mode` 支持 3 种，P0 只实现 2×1，避免 v4 改表。

### 8.2 ER 关系

```
rooms 1──N dolls
rooms 1──N guests
guests 1──N progress N──1 dolls
dolls 1──N assets
dolls 1──1 gen_tasks（最近一次）
rooms 1──N events
```

### 8.4 JSON 字段结构

**`rooms.finale_json`**

```json
{
  "enabled": true,
  "trigger": { "type": "all_collected", "value": null },
  "title": "你今晚见到了我们全家",
  "body": "最后这一位，是一直在厨房忙的那个人。",

  "model_url": null,
  "reward_note": "拿着这一页去找主人，换一张贴纸",
  "share_caption": "今晚我认识了 6 个人",
  "opened_at": null
}
```

**`dolls.options_json` / `synonyms_json`**：字符串数组；`options_json` 仅 `single_choice` 使用，长度 2–4。

**`progress.state` 迁移规则**（服务端强制，PRD 13）：

| 当前 | 事件 | 目标 | 是否幂等 |
|---|---|---|---|
| `locked` | 扫码/短码命中 | `discovered` | 是（已 discovered 保持不变） |
| `locked`/`discovered` | E1 演出结束 / 跳过 | `collected` | 是（已 collected 不降级） |
| `collected` | 点「再听听」 | `egg_answering` | 是 |
| `egg_answering` | 答错 | `egg_answering` | 是（只累加 attempts） |
| `egg_answering` | 跳过/离开 | `collected` | 是 |
| `egg_answering` | 答对 | `egg_unlocked` | 是（已解锁不重复发 ticket） |
| 任意 | 任何事件 | **不得回退** | 用 SQL 条件更新保证 |

> **零卡关的实现保证**：`discovered`/`collected` 的写入只依赖 `POST /api/play/discover`，不依赖判题结果；该接口失败仅重试，不回滚状态。

### 8.5 并发与事务

- better-sqlite3 单连接同步执行，Node 单线程天然串行；WAL 下读写不互斥；
- 关键事务：
  1. `join`：插入 guest（UNIQUE room_code 校验在 rooms）；
  2. `scan`：`GET /api/play/d/:token` 命中时 upsert `progress.state='discovered'`（幂等；GET 落状态是刻意取舍，用于看板区分「已发现/已收藏」，重复扫码不变）；
  3. `egg/start`：`UPDATE progress SET state='egg_answering'`（仅当已 `collected` 且该卡启用彩蛋题，幂等）；
  4. `answer`：答错 `attempts+1`（状态保持 `egg_answering`）；答对 `state='egg_unlocked'` + `egg_unlocked_at` + 写 `events` + 判终局 + 写 `finale_reached`（同一事务）；
  5. `discover`：`INSERT ... ON CONFLICT DO UPDATE` 条件更新（不降级），与终局判定同一事务；
- 8 台设备并发时，写操作排队在毫秒级；读走 WAL 快照；
- `busy_timeout=5000` 兜底；DB 异常返回 503 且前端可重试。

### 8.6 迁移与备份

- `schema_meta` 存 `schema_version`；启动时按 `migrations/001_init.sql, 002_*.sql` 顺序执行，每个迁移一个事务；
- 迁移前自动备份到 `data/backups/home-<timestamp>.db`，保留 5 份；
- 备份/恢复：`GET /api/host/backup`（下载 db）与 `POST /api/host/restore`（上传 db，校验版本后替换）；也可直接拷 `data/`；
- 一键清空（PRD FR-13）：`DELETE /api/room/:id/data` 事务内清空 progress/guests/events/assets，删除照片/模型/导出文件，**保留房间配置与预置资产**，二次确认。

### 9.4 两级 ticket 规格（安全核心）

**格式**

```
t1.<base64url(payload)>.<base64url(HMAC-SHA256(secret, "t1."+payload))>
payload = { "v":1, "s":"base"|"secret", "d":"<doll_id>", "g":"<guest_id>", "e":<unix秒>, "n":"<8位随机>" }
```

**签发**

| 场景 | scope | 用途 | TTL |
|---|---|---|---|
| `/api/play/d/:token`、`/api/play/shortcode` | `base` | 主 GLB、基础故事、原图 | 60s |
| `/api/play/answer` 正确 | `secret` | E2 故事、第二形态 GLB、悄悄话 | 60s |
| `/api/collection` 每次 | `base`（及已解锁的 `secret`） | 展柜按需加载 | 60s |

**校验**（`/api/assets/:doll/:kind`）

1. 解析 ticket → 验签（`timingSafeEqual`）→ 验 `exp` → 验 `scope` 与 `kind` 匹配 → 验 `doll_id` 与路径一致 → 验 `guest_id` 属于该 room；
2. 不通过：403 `TICKET_INVALID` / `TICKET_EXPIRED` / `TICKET_SCOPE_MISMATCH`；
3. 通过：流式返回文件，支持 Range。

**设计取舍**

- 无状态签名，不建 ticket 表；60s 内可重放（同 WiFi 抓包也需先拿到 URL），威胁模型可接受（见 10.1）；
- 密钥 `data/secret.key`（32 字节随机，0600）；轮换密钥 = 全部 ticket 立即失效，不影响已登录会话（会话用独立密钥派生）；
- ticket 只出现在 URL query，访问日志脱敏（不打印 query）。

## 10. 安全设计

### 10.1 威胁模型

| 角色 | 能力 | 可能做的事 | 影响 | 对策 |
|---|---|---|---|---|
| 同 WiFi 的客人 | 有浏览器、能看 F12、能抓包 | 猜 token / 改 URL 跳关 / 看答案 / 伪造别人进度 | 中低（进度无经济价值） | 不可枚举 token、服务端判题、两级 ticket、guest_token 签名 |
| 拿到他人手机的客人 | 能看 localStorage | 看已收藏内容 | 低（本就是同一场合） | 无额外对策（可接受） |
| 不在 WiFi 的陌生人 | 无入口 | — | 无 | 私有 IP 天然隔离 |
| 主人电脑的其他本地用户 | 能开 localhost | 进管理端 | 中 | PIN + 会话；默认不接受非回环 |
| 恶意网页/脚本 | 只能诱导点击 | 盗 token | 低 | CSP、SameSite、无外链、HTML 转义 |
| 专业网络攻击者 | 可 ARP 嗅探 HTTP | 看到 PIN/答案/token | 高（但非目标场景） | **明确不承诺**；参见 10.6 |

### 10.2 资产保护矩阵

| 资产 | 下发时机 | 凭证 | 无凭证结果 |
|---|---|---|---|
| 主 GLB / 基础故事 / 原图 | 扫码后（E1） | `base_ticket`（60s, scope=base） | 403 |
| E2 隐藏故事 / 第二形态 / 悄悄话 | 判题通过后 | `secret_ticket`（60s, scope=secret） | 403 |
| 剪影 PNG / 二维码 PNG | 公开 | 无 | 正常（不泄密） |
| 答案哈希 / 同义词 / `hide_hint` / 备用 token | **永不下发** | — | 不在任何响应中 |
| 他人进度 / 房间终局内容（未达成） | 不下发 | — | 前端不请求、服务端不返回 |

**验收钩子**：自动化脚本对**未认证响应、未答对响应、SSR HTML、构建产物**做全量字符串扫描，断言不含测试种子答案、`answer_hash`、`synonyms`、`secret` 内容、`hide_hint`、`token_backup`；**答对后的响应按契约应包含 `secret_ticket` 与 E2 内容，属于授权内容，不参与该扫描**（单独用契约测试断言字段齐全且只能凭 `scope=secret` 拉取）。

### 10.3 答案保护细节

- 写入：`answer` 明文只在请求体中出现一次，服务端立即归一化 + `scrypt`（N=16384, r=8, p=1, salt=16B）+ 立即丢弃；
- 比较：`timingSafeEqual`；同义词逐条比较，命中任一即正确；
- 单选：前端只提交下标，**正确下标不落库**（由哈希反推）；选项顺序可随时调整而不泄露答案；
- 判题接口限流 + 统一文案（错误不区分「答案错」与「选项越界」）；
- 日志：只记录 `correct: boolean`，不记录提交内容。

### 10.4 管理端

| 项 | 设计 |
|---|---|
| PIN | 4–8 位数字，scrypt 哈希；首次运行强制设置；错误 5 次/分钟后限流 |
| 会话 | HMAC cookie（HttpOnly, SameSite=Strict, 12h）；`pinv` 变更即全部失效 |
| 本机限制 | 默认拒绝非回环地址；`host.allowLanAdmin` 可放开（手机看看板） |
| CSRF | SameSite=Strict + 自定义头 `X-WTM-CSRF` + `Origin` 校验 |
| 越权 | 所有资源路由先校验 `room_id` 属于当前会话主人；单房间场景简化但保留校验点 |
| 敏感操作 | 清空数据、删人偶、结束房间均需二次确认（前端对话框 + 后端 `confirm: true`） |

### 10.5 隐私

- 照片、GLB、进度只存 `./data/`，不上传任何第三方；生成期例外（Lux3D 云端，需在授权说明中写明）；
- 上传照片经 sharp 重编码，**自动剥离 EXIF（含 GPS）**；
- 首次进入的授权说明：内容用途、存储位置、生成期出网、可一键清空；
- 不接第三方统计、不引外链字体/图片、不发邮件；
- 涉及未成年人/已故亲人：主人端首次提示「请确认已获授权」，路线图只开离线对话树；
- 一键清空：删除原图、模型、导出、进度、埋点，保留房间配置；操作日志保留「已清空」记录但不含内容。

### 10.6 HTTP 明文的边界（必须写清）

局域网纯 HTTP 意味着：

- **PIN 只在本机 `localhost` 输入**，不经过局域网，故不会被同网段嗅探；
- 客人的 `guest_token`、答题内容、ticket 在 WiFi 中明文传输，**同网段的专业攻击者可以嗅探并伪造该客人的进度**；
- 影响评估：进度是游戏数据，无经济价值；房间本身是「请朋友来家里玩」的信任场景；
- **明确不做**：不引入 HTTPS（PRD 硬约束）、不做应用层加密（徒增复杂度且无法防重放）；
- 若主人需要更强隐私，可在路由器上隔离客人网络（AP isolation 会阻断访问，故不推荐）或仅邀请可信客人。

### 10.7 构建与供应链

- 依赖锁版本 + `npm ci`；D1 跑一次 `npm audit` 并记录；
- 构建后扫描：`http://` / `https://` 外链（白名单：许可证注释、SVG 命名空间）；
- 自托管资源：three.js、DRACO wasm、Noto 字体、二维码库；
- CSP：

```
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';      /* 内联 critical CSS 与动画需要 */
img-src 'self' data: blob:;
media-src 'self' blob:;
font-src 'self';
connect-src 'self';
frame-ancestors 'none';
base-uri 'none';
form-action 'self';
```

- CORS：**不开放跨域**（同源 SPA）；如需调试，`Access-Control-Allow-Origin` 只允许 `host.corsAllowlist` 中显式列出的地址，默认空；
- 其他头：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Permissions-Policy: camera=(), microphone=(), geolocation=()`（**再上一层保险：显式禁用摄像头**）；
- 代码级扫描：CI 断言源码与产物中无 `getUserMedia`、`navigator.xr`、`<script src="http`。

## 11. 非功能设计

### 11.1 性能预算与测量

| 指标 | 目标 | 测量点 | 降级策略 |
|---|---|---|---|
| 首屏可读（SSR 内容出现） | < 1s（局域网参考机） | `navigationStart → first-contentful-paint` | 内联 CSS、无阻塞字体 |
| 扫码 → 页面可交互 | < 3s（含系统相机切浏览器） | 真机秒表 / `navigationStart` | 微信引导页、短码兜底 |
| **E1 首帧特效** | **< 300ms**（从脚本执行起） | `e1:boot → e1:firstframe` | 看门狗降级为 CSS 版 |
| 主模型可见 | < 3s | `e1:model` | 剪影静帧 + 进度点 |
| E1 总时长 | 2.6s（可跳过） | `e1:settle` | `reduced-motion` 直出静帧 |
| E2 总时长 | 1.5–2.5s | `e2:start → e2:done` | 跳粒子，只保留文案 |
| 判题响应 | < 200ms（局域网） | 服务端 p95 | 超时 3s 提示稍后 |
| 看板刷新 | 2s 内 | SSE 事件延迟 | 轮询兜底（5s） |
| 服务内存 | < 512MB | 进程 RSS | 单进程足够 |
| 并发 | ≥ 8 台 | 并发脚本 | — |

**测量实现**：`performance.mark/measure` + `PerformanceObserver`；只在开发与验收环境打点，生产默认关闭详细打点（可配置）。

### 11.2 并发模型

- Fastify 单进程 + better-sqlite3 同步写：8 台设备的写请求排队在亚毫秒级；
- 读多写少：收藏册/看板读走 WAL 快照，不阻塞写；
- SSE 连接：主人 1 + 预览 1，上限 8；心跳 15s，避免代理超时（无代理，仍保留）；
- 生成队列并发 1，与游戏期隔离（房间 live 时禁止触发生成，除非主人显式确认）；
- 压测脚本：`scripts/load-test.ts` 模拟 8 guest × 6 doll 全流程，断言无 5xx、无串号。

### 11.3 兼容性矩阵

| 环境 | 承诺级别 | 验证 |
|---|---|---|
| iOS Safari 16+（iPhone） | 完整通关 | 真机 |
| Android Chrome 100+（含中低端） | 完整通关 | 真机 2 台 |
| 桌面 Chrome / Safari / Edge | 完整通关 | 自动化 + 手测 |
| 微信内置浏览器（iOS/Android） | 尽力兼容，不承诺 | 真机，异常时引导「在浏览器中打开」 |
| UC / QQ 浏览器 | 不承诺 | 不做专项 |

**卡片页必须做到**：即使 JS 完全失败，SSR 页面仍显示名字、剪影、基础故事与「收藏」按钮（`<form>` 提交 discover）。

### 11.4 网络异常与降级

| 场景 | 表现 | 处理 |
|---|---|---|
| 手机切蜂窝 | 首页/卡片页 5s 超时 → 显示「连的是主人家 WiFi 吗」+ 重试 | 不自动跳转 |
| 路由器 AP 隔离 | 自检页提示；客人看到「无法连接」 | 主人检查路由器 |
| 微信拦截私有 IP | 显示引导页（复制链接到系统浏览器） | 短码 + 手动输地址 |
| IP 变化 | 卡片二维码失效；短码仍可用 | 自检页对比当前 IP 与 `rooms.lan_ip`，提示重导出 |
| 断外网 | 完全不影响游戏 | 生成期外网不可用则用预置 |
| 服务重启 | SQLite 恢复，进度保留 | 启动自检 + 日志 |

### 11.5 可移植与运维

- 启动：`node dist/server/index.js`（`npm start`）；`--port`/`--host`/`--config` 可选；
- 数据：`./data`（SQLite、照片、模型、导出、日志、密钥）；配置：`./config`；
- 迁移：拷目录 + 改 `config/local.json` 的 IP/端口；
- 无守护进程要求：macOS 用 `caffeinate -s` 防睡眠；可选 launchd 配置（附录）；
- 日志轮转：按天，保留 14 天；磁盘不足 200MB 时告警（自检页显示）。

### 11.6 无障碍

- `prefers-reduced-motion: reduce` → 无粒子、无翻牌，直接静帧 + 内容；
- 所有按钮可 Tab 聚焦，焦点环可见；`aria-live="polite"` 播报判题结果；
- 不依赖颜色单独传达状态（彩蛋角标用文字「彩蛋 0/1」+ 图形）；
- 对比度 ≥ 4.5:1（正文）；字幕式文案（名字/故事）大字号可读；
- 音效可关；关键信息不依赖音频。
