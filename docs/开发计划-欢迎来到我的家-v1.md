### 0.1 三条排期假设（若与实际不符，按相对天数平移）

| # | 假设 | 依据 | 影响 |
|---|---|---|---|
| A1 | 提交截止 **2026-11-19（周四）19:00** | 群核 Aholo 黑客松既往节点（前序项目文档） | 核心开发 11-08 → 11-15，11-16 → 11-19 为打磨与提交缓冲 |

- **阶段用 S0–S7**，避免与 PRD 的功能优先级 `P0/P1/P2` 撞名（PRD 第 18 章的 `P0–P6` 在本计划中依次对应 S1–S7，S0 为本计划新增的工程准备）。

### 0.3 交付物总目标

> **11-15 结束时，一位客人、一台手机，能在主人家 WiFi 下，从扫码到 E1 彩蛋、收藏、可选题、E2、终局完整通关，且全程不答题也能通关；主人能独立配置并打印卡片。**

## 4. 团队分工

### 4.1 三角色（3 人版）

| 代号 | 角色 | 负责范围 | 不负责 |
|---|---|---|---|
| **A** | 后端 / 基础设施 / SSR | Fastify、SQLite、ticket、判题、终局判定、SSE、SSR 卡片页、PDF 生成、安全与并发、部署 | 特效、主人端 UI 细节 |
| **B** | 客人端 / 特效 | E1/E2 引擎、three.js、收藏册、终局页、降级与性能、真机兼容 | 管理端表单、生成管线、SSR 模板 |
| **C** | 主人端 / 物料 / 生成 | 主人端 SPA、关卡与终局配置、预览、看板 UI、token/短码/二维码、PDF 版式与打印、Lux3D/Blender 管线、演示素材 | 服务端核心、特效引擎 |

**交叉评审**：每天至少 1 次 PR 互评（A↔B 接口、B↔C 预览页、C↔A 卡片/看板接口）。

### 4.2 两人版（若只有 2 人）

| 调整 | 做法 | 代价 |
|---|---|---|
| 合并角色 | A 承担 A+C 的服务端与 PDF；B 承担客人端 + 主人端（表单简化） | 主人端用 JSON 表单 + 少量样式，不做精细交互 |
| 砍范围 | 生成链路只保留「手动上传 GLB」；看板简化为轮询表格；预览模式降为「只读预览」 | 少 2 个魔法时刻的自动化，但玩法闭环完整 |
| 工期 | 10–12 天；或保持 8 天并把 D7–D8 的真机与打磨压到 1 天 | 风险显著上升，需提前锁 D4 门禁 |

### 4.3 单人极限版（不推荐）

只做：预置 6 人偶 + 固定 discovery/bonus_quiz + E1 简化特效（CSS 翻牌 + 少量粒子）+ 收藏册 + 终局（all_collected）+ 卡片 PDF（HTML 打印）。**砍掉：E2 第二形态、四主题、看板、生成链路、预览模式。** 预计 6–8 天，仅够 demo。

## 11. 协作规范

### 11.1 仓库与分支

- 主干 `main` 始终可运行；功能分支 `feat/<task-id>-<slug>`；修复 `fix/<slug>`；
- PR 必须：CI 绿 + 1 人 review + 关联任务 ID；合并用 squash；
- 提交信息：`feat(T501): 时间轴引擎与看门狗`、`fix(T403): discover 幂等竞态`；
- 每日 20:00 后只允许「修复类」提交，功能提交次日再合。

### 11.2 代码规范

- TypeScript `strict: true`；禁止 `any` 泛滥（必要处写注释）；
- 接口类型集中在 `src/shared/contracts.ts`，前后端共用；
- 组件/模块单一职责；特效代码不得直接调 API；服务端不得拼 HTML 字符串不经转义；
- 新增依赖必须说明理由（体积/离线/维护性），优先零依赖实现。

### 11.3 资产与数据

- 预置 GLB/剪影/字体入 git（体积小）；运行时 `data/` 不入 git；
- 大文件（>10MB）用 Git LFS 或共享盘，禁止直接提交；
- 测试照片使用虚构素材，禁止用真实家庭照片做测试数据；
- 提交前清理 `data/`、日志、临时导出。

### 11.4 沟通节奏

| 时间 | 事项 | 形式 |
|---|---|---|
| 每天 10:00 | 站会 15min | 昨天完成 / 今天计划 / 阻塞 |
| 每天 13:00 | 联调窗口 | A+B 或 A+C 结对 30min |
| 每天 20:00 | 合并截止 | main 可运行 |
| 每天 21:00 | 门禁检查 | 按当日 Gate 记录 |
| 随时 | 阻塞 >2h | 群里 @ 全员，不静默 |

### 11.5 文档与变更

- PRD 不改写（作为权威输入）；技术方案变更在文档「变更记录」追加；
- 接口/数据模型变更必须同时更新技术方案对应章节；
- 砍刀线执行后，在开发计划末尾记录「日期 + 决策 + 影响」。
